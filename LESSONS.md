# LESSONS

[2026-07-19] Lesson: create-next-app fails in a Hebrew-named directory. Reason: npm package names must be ASCII. Fix: scaffold into a latin-named subfolder with --skip-install, then move contents up.
[2026-07-19] Lesson: pinned Gemini model ids (gemini-2.5-flash) return 404 for new API users once sunset. Reason: Google retires old models for new keys. Fix: use the rolling alias gemini-flash-latest.
[2026-07-19] Lesson: PostgREST embed profiles(...) from recipes fails with PGRST201 once schema cache refreshes. Reason: favorites/ratings create extra many-to-many paths to profiles. Fix: always disambiguate embeds with !fkey_name.
[2026-07-20] Lesson: an RLS-blocked delete via PostgREST returns success with zero rows, so a follow-up admin/storage mutation ran for non-owners. Reason: RLS filters rows instead of erroring. Fix: verify ownership explicitly and require .select() proof that the delete affected a row before any service-role side effect.
[2026-07-21] Lesson: the in-app Browser pane could not fire React onClick (synthetic .click() no-op, refs resolved to 0,0, stale SPA shells) and a mid-build next.config change corrupted .next/dev/types/routes.d.ts causing phantom 404s. Fix: rm -rf .next and rebuild; verify interactive React flows through the real Chrome extension (mcp__claude-in-chrome) against the live URL, not the in-app pane.
[2026-07-21] Lesson: rendering a <div> (StepTimerButton) inside a <p> caused a hydration error that can break client interactivity on that subtree. Fix: wrap block-level step content in <div>, never <p>.
[2026-07-20] Lesson: JS regex \b never fires next to Hebrew letters (it is defined on [A-Za-z0-9_]), so "40 דקות" was not matched. Fix: use an explicit negative lookahead like (?![א-תa-z]) instead of \b for Hebrew text.
[2026-07-20] Lesson: cup->gram conversion needs a per-ingredient density (flour 120g/cup, sugar 198, honey 336) - a single factor is wrong. Fix: keyword-match the free-text name against a density table and fall back to volume-only conversion when unknown, never invent a weight.
[2026-07-20] Lesson: ingredient rows collapsed to empty squares on mobile. Reason: cn() only concatenates, so a caller's w-14 never overrides the Input base w-full; the sibling flex-1 field then got zero width. Fix: size such rows with a CSS grid on the parent (grid-cols-[3.25rem_4.5rem_1fr_2rem]) instead of per-child width classes.
[2026-07-21] Lesson: PushManager.subscribe applicationServerKey rejects a plain Uint8Array under TS strict (buffer typed ArrayBufferLike, not ArrayBuffer). Fix: build the array over an explicit `new ArrayBuffer(len)` and return Uint8Array<ArrayBuffer>.
[2026-07-21] Lesson: closed-app timer notifications need a real server push - browser Notification only fires while the tab's JS is alive. Fix: Web Push (VAPID + SW) with a server scheduler; Vercel Hobby cron is daily-only so use Supabase pg_cron + pg_net to POST a secret-guarded dispatch endpoint every minute. iOS requires the PWA installed to the home screen.
[2026-07-21] Lesson: measurement system is now derived from locale (systemForLocale: en=us, else metric), not a separate profiles.unit_system toggle. The column stays but is written to match locale; do not reintroduce a standalone units switch.
[2026-07-24] Lesson: next-intl getTranslations({locale})/getMessages({locale}) silently returned the cookie locale because src/i18n/request.ts getRequestConfig ignored its argument. To render one recipe in a non-cookie language, getRequestConfig must accept `({ locale })` and honor it when valid, falling back to the cookie only when absent. Symptom: recipe text translated but labels/units stayed in the app language.
[2026-08-27] Lesson: THE real quota ceiling - every Gemini free-tier model has its OWN tiny daily allowance, measured from the 429 body as quotaId "GenerateRequestsPerDayPerProjectPerModel-FreeTier" with quotaValue **20 requests per day per model**. Funnelling all work through one primary model therefore capped the family at ~4 recipes/day (each recipe costs extraction + translation + title). Fix: spread across FIVE models (gemini-3.6-flash, gemini-flash-latest, gemini-3.5-flash, gemini-flash-lite-latest, gemini-3.5-flash-lite); translation leads with the lite models and keeps the strong ones for reading photos. A PerDay 429 marks that model exhausted for the calendar day (module-level map) and falls straight through - never retried. Classify with /PerDay/i on the quotaId, NOT loose words like "daily". Verified: translation succeeded in 1.3s via flash-lite while 3.5-flash was fully spent.
[2026-08-27] Lesson: "Today's free AI quota is used up" appeared after only ~4 recipes while our own counter showed 25/150 - so it was NOT our cap. Gemini returns 429 for BOTH the daily quota and a short per-minute rate limit, and the code treated every 429 as "come back tomorrow". Now the 429 body is classified (isDailyQuota -> /per\s*day|daily/i): daily -> GeminiQuotaError, otherwise GeminiBusyError with a 6s backoff and an "AI is busy, try again in a minute" message. The courtesy cap was also raised 150 -> 500 (the no-billing key cannot be charged, so Gemini's own limit is the real ceiling).
[2026-08-27] Lesson: translate on WRITE, not only on read. createRecipe/updateRecipe now schedule pretranslateRecipe() via after(), which caches both the full translation and the list title in the other language, so a newly added recipe opens instantly instead of triggering a live translation on first view.
[2026-08-26] Lesson: translated recipes still showed English measurement words ("1 big bunch פטרוזיליה", "3 cloves שום") because the prompt told the model NOT to translate the unit, on the assumption the display layer localizes it - but display only localizes units resolveUnit RECOGNIZES; anything else falls through as raw free text in the source language. Fix (two parts): (1) UNITS/UNIT_ALIASES now cover the countable units recipes actually use - clove/bunch/handful/sprig/stalk/slice/can/container/dash/drop in both languages, with singular+plural labels in messages; (2) translateRecipe now also returns ingredient_units and mergeTranslation applies them. Translating a unit is safe because resolveUnit maps both languages to the same canonical id, so canonical units still get properly inflected and only free-text ones are rescued.
[2026-08-26] Lesson: recipes opened in the other language rendered UNTRANSLATED after a long hang, because translation used a SINGLE model (`[TRANSLATE_MODEL]` = gemini-flash-latest) with thinking:high - the same overloaded combination that broke photo extraction - while extraction had a fallback chain. Translation now uses the same chain (3.5-flash first) at thinking:low: the exact recipe that failed translates in 11.6s first try. Whenever you add a Gemini call, give it the chain; never a lone model.
[2026-08-26] Lesson: never let a page render block on Gemini. fetchRecipeForReader now waits at most ON_DEMAND_TRANSLATE_MS (22s); past that it returns the ORIGINAL with translationPending=true, finishes the work in after() with the admin client, and <TranslationPending/> shows "מתרגם את המתכון..." and auto-refreshes. Guard the retry: the auto-refresh would otherwise re-trigger translation and re-bump the daily cap on every reload (module-level translateAttempts map, 90s).
[2026-08-26] Lesson: detectLang used to return 'he' if the text contained ANY Hebrew character, so an English recipe with one Hebrew word was treated as Hebrew and never translated. It now compares Hebrew vs Latin letter counts (dominant script wins), and detectRecipeLang lets the BODY (ingredients+steps) decide with the title only breaking a tie.
[2026-08-26] Lesson: photo extraction kept failing because `thinking_level:"high"` on IMAGE workloads makes Gemini return 503 "model is overloaded" almost every time (measured: 503 at 31s with 2 images, 503 at 26s with 1). Turning thinking off worked but took 59s against a 60s maxDuration - no headroom, so slow-but-fine extractions were killed by the platform. FIX: photos use `thinking_level:"low"` (14-21s, reliable), text/translation keep "high"; `gemini-3.5-flash` leads the chain (faster + steadier on photos than flash-latest); per-attempt timeout 45s, budget 95s, and route maxDuration raised 60 -> 120. Verified 5/5 real scans succeeded first try in 6-23s. NOTE `thinking_level:"minimal"` is rejected with 400 - the floor is "low".
[2026-08-26] Lesson: don't debug production blind - `vercel logs` only returns the last ~100 lines and the per-minute pg_cron dispatch floods it. Reproduce instead: pull a real image out of Supabase storage with the service-role client and replay it against the API with the exact production config.
[2026-07-28] Lesson: "photo extraction failed once then worked" was Gemini returning 503 "experiencing high demand" with NO retry in the chain. Measured worse: an overloaded call can hang 234s before answering, which blows the route's 60s limit entirely. Fix = per-attempt AbortSignal.timeout (20s) + 2 attempts per model + fallback model + a 40s whole-request budget. Verified live: attempt1 timed out at 20s, attempt2 got 503, gemini-3.5-flash then answered 200 in 5.7s (35s total). Never call Gemini without an AbortSignal.
[2026-07-28] Lesson: Hebrew recipe steps must be translated in the impersonal present plural ("מבשלים", "מחממים"), not the infinitive ("לבשל"). Gemini defaults to the infinitive unless the prompt gives explicit WRONG/RIGHT examples; with them, 0/4 steps came back wrong.
[2026-07-27] Lesson: calling a next-intl message that has a placeholder without its value (t('photoBy') then .replace('{name}',...)) throws FORMATTING_ERROR on the server. Interpolate on the server (t('photoBy', { name })) and pass the finished string to the client component.
[2026-07-27] Lesson: the share card is 1080x1440 (3:4 page format) with a two-column editorial layout (ingredients side column, photo + method main column) in Frank Ruhl Libre. Canvas never downloads a webfont on its own - `await document.fonts.load('700 64px <family>')` for every face before drawing or it silently falls back. When a long recipe does not fit, shrink the PHOTO first (candidates 430/360/290/210) and only then the text, otherwise the text hits min scale while the page stays half empty.
[2026-07-26] Lesson: share-card.ts is now direction-aware - pass `dir` from ShareData (locale) and mirror every element (startEdge/inward helpers) instead of hardcoding ctx.direction='rtl' + textAlign='right', which rendered English cards RTL. Meta-row cells are also laid out in reading order. Use canvas-drawn line icons, NOT emoji: emoji glyphs render wildly differently per platform (🍳 came out as a purple blob).
[2026-07-26] Lesson: never block a list render on Gemini. attachTranslatedTitles serves cached titles synchronously and schedules missing ones with `after()` from next/server (Next 16). Inside `after()` in a Server Component request APIs (cookies) are restricted, so use createSupabaseAdminClient there - the recipes were already RLS-filtered for the caller.
[2026-07-26] Lesson: Next.js App Router ignores folders prefixed with `_` (private folders) - `src/app/api/_devsave/route.ts` 404s. Name it without the underscore.
[2026-07-26] Lesson: deleteRecipe removed storage photos BEFORE deleting the row, so an RLS-blocked delete destroyed the photos anyway. Always delete the row first with `.select()` proof, then clean storage.
[2026-07-25] Lesson: display-units no longer converts cups->grams (that produced "49.5 גרם שמן זית"). New rule: volume (cup/tbsp/tsp/ml/liter), length and count are kept EXACTLY as written (only the unit word is translated + a clean fraction), and ONLY weight cross-converts between systems (metric g/kg <-> US oz/lb). ingredient-density.ts is now unused. Mirrors English: "¼ cup" <-> "¼ כוס".
[2026-07-25] Lesson: recipe TITLES in list views (home/favorites/search) are translated to the reader's app language via a batched Gemini call cached in recipe_title_i18n (migration 009), applied in queries.attachTranslatedTitles. Inside the recipe page the title already comes translated from fetchRecipeForReader; the lists were the gap.
[2026-07-25] Lesson: any family member can add DISH photos (migration 010 adds recipe_photos.uploader_id; RLS split so non-owners insert kind='photo' on family-visible recipes; owner or uploader can delete). A badge ("hover 📷 by <name>") shows on photos where uploader_id != recipe.owner_id. Storage bucket 'photos' already allowed any authenticated upload, so only the table RLS needed changing.
[2026-07-25] Lesson: the extractor rejected a clear ingredient-only note ("not recognized") because it required ingredients AND steps (route gate + prompt is_recipe rule). Recipes are often just an ingredient list (sauces/dips/spice mixes/drinks). Fix: is_recipe true for ingredients OR steps; route accepts when either is non-empty; recipeFormSchema.steps is now optional (min removed); recipe page/share/cook hide the steps section when empty. Also: screenshots carry app UI (call banners, checkboxes, thumbnails) - the photo prompt now says to ignore all chrome and read only the recipe content.
[2026-07-25] Lesson: `gemini-2.5-flash` and `gemini-2.5-flash-lite` return 404 "no longer available to new users" for this API key; only the Gemini-3 Flash line works (`gemini-flash-latest`, `gemini-3.5-flash`), both accept `thinking_config.thinking_level:"high"` (2.5 used `thinking_budget`). Extraction uses a fallback chain (flash-latest -> 3.5-flash) since 3.5-flash can transiently 503. A no-billing key can only draw free quota (429), never a charge, so model choice carries zero cost risk. Verify model IDs with a live probe before pinning.
[2026-07-24] Lesson: recipe view language is a TRANSIENT per-recipe override via `?lang=he|en` (not the persisted cookie). The recipe/cook pages read searchParams -> viewLocale (default = settings locale), wrap content in a nested NextIntlClientProvider(locale=viewLocale, messages=getMessages({locale:viewLocale})) with dir set per viewLocale, and pass viewLocale to fetchRecipeForReader/systemForLocale/buildShareData. The in-recipe LanguageToggle sets the URL param (router.replace), it must NOT call setLocale. Leaving the recipe drops the param -> back to settings language.
[2026-08-30] Lesson: Piping curl output straight into python on this machine decodes stdin as cp1255 and mangles Hebrew, so string checks silently fail. Reason: Windows console codepage, not the file content. Fix: write the response to a file and read it with io.open(..., encoding='utf-8'), or set PYTHONIOENCODING=utf-8.
[2026-08-30] Lesson: next-intl ships the entire message bundle inside the HTML payload, so grepping a page for a translated string always matches. Reason: the whole namespace is serialized for the client provider. Fix: verify server-rendered state by structural markers (a form field name, a component-only element) or by stripping <script> before matching text.
[2026-08-30] Lesson: Instagram serves servers a 605KB page with zero og: tags and no caption, but yt-dlp still reads it fine, anonymously, including from a Vercel datacenter IP. Reason: yt-dlp bootstraps a cookie session first ("Setting up session") before requesting the post. Fix: do not hand-roll an Instagram scraper - shell out to yt-dlp and let it track the changes.
[2026-08-30] Lesson: A `'use server'` file may only export async functions, so a sync helper next to a server action breaks the build. Reason: every export becomes a callable server action. Fix: put pure helpers in a plain module (safeNextPath lives in lib/recipe-url.ts).
[2026-08-30] Lesson: Vitest hides console.log from passing tests, which makes "prove the output is good" runs look empty. Reason: default console interception. Fix: run with --disableConsoleIntercept when the point of the run is to read the output.
[2026-09-11] Lesson: "the photo saved and then vanished" was recipe-editor's save(): each upload did `if (error) throw error`, and `addRecipePhotos` sat AFTER both loops inside the same try - so one failed upload skipped the database write for every photo that HAD uploaded. Reason: collect-then-commit inside a try that the collection can abort. Fix: upload each photo independently with retries (lib/photo-upload.ts), always record what succeeded, and never celebrate or navigate on a partial save.
[2026-09-11] Lesson: client-side failures were completely invisible - a browser upload that died left no trace anywhere and could not be investigated. Reason: only server routes logged. Fix: client_events table (migration 015) + /api/log + lib/client-log.ts with `keepalive: true` so the report survives the navigation that follows it.
[2026-09-11] Lesson: "not recognized" with no reason taught people to give up and retype everything. Fix: the extraction schema now returns reject_reason (handwriting/blurry/dark/cropped/empty/notRecipe/other), the 422 carries it, and the form explains the cause, promises the photo is kept, and offers to continue by hand. Verified live: a real scan still returns reject_reason=null with 14 ingredients, a blank image returns "empty".
